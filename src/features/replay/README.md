# Replay 결과·통합 회고 (P1-03)

담당 범위는 데스크톱 결과·통합 회고다. P1-01 지난 뉴스와 P1-02 학습 패턴, 모바일은 포함하지 않는다.

- 디자인: Figma `qnwfwZtYuzz6YwibShM2JE`, `427:135` 및 기간·금리·저장 완료·상태 시안.
- `/dev/replay/preview/results`: 명시적인 개발 목. 두 대상, 1·5·20거래일, 원시 변화량과 금리 %p, 그래프, 통합 회고, 이탈 보호, 저장 실패/응답 유실 재시도, 새로고침 후 읽기 전용 확인. 브라우저 탭의 sessionStorage만 사용하며 서버 저장이 아니다. 목과 미리보기는 배포 빌드에서 제외한다.
- `/replay/:replayId/results`: 운영 진입 경계만 등록. 현재는 준비 중 안내다. 쿼리나 로컬 플래그로 결과를 공개하지 않으며 HTTP 실패를 목 성공으로 바꾸지 않는다. P0 메뉴에는 미완료 Replay 진입 링크를 추가하지 않는다.
- `ReplayData`, `ReplaySaveRequest`, `ReplayReceipt`는 FE 내부 표시·콜백 인터페이스다. 확정 HTTP 명세가 아니며 새 서버 엔드포인트나 `replay_final` 요청을 임의로 추가하지 않았다.
- 단일 회고는 대상·기간을 바꿔도 유지된다. 세 질문 중 공백이 아닌 답변 하나 이상이 필요하다. 동일 답변 재시도는 같은 요청 ID를 사용하고, 응답 ID·본문을 검증한 뒤 읽기 전용으로 전환한다.
- 결과 미공개·조회 실패·빈 자료에서는 수치·그래프·회고 폼을 마운트하지 않는다. 관측 불가 기간에서는 수치와 그래프를 숨기고 다른 기간 및 통합 회고는 사용할 수 있다. 일별 자료가 없으면 보간하지 않는다. 대상·단위·기간·확정값이 다른 그래프도 숨긴다.

## BE 연결 시 확인할 항목

현재 로컬 BE는 Replay 세션 생성을 거부하며 `replay_final` 저장을 받지 않는다. API MD에서도 P1 보류다. FE 완료를 실제 연동 완료로 해석하지 않는다.

1. `replayId`와 `learningSessionId`의 관계 및 P1-01에서 넘겨줄 식별자. 둘이 같다고 가정하지 않는다.
2. 예측 제출·최초 피드백 확인 후의 명시적 결과 공개 요청과 서버의 `resultsRevealedAt` 검증. 공개 전 응답에도 결과·가격·그래프를 포함하지 않아야 한다.
3. 과거 T0·거래일 달력·출처·시계열 조회 계약. 현재 제출 시각 기준의 live T0를 재사용하지 않는다.
4. 통합 회고 저장/조회 형식, `replay_final` 허용 여부, 최소 한 답변·요청 ID 중복 방지·응답 유실 재조회 규칙, 완료 상태와 저장 시각.
5. 완료 Replay의 학습 기록 링크 및 최초 피드백 재방문 경로.

명세 확정 후 실제 어댑터가 `ReplayResultsView`의 data/save에 연결되면 된다. BE 원본·DB는 변경하지 않았다.

## UI 보완

- P1-03 최종 시안에 맞춰 세 기간의 변화·당시 예측을 비교하는 선택 카드, 기준·관측 수치와 날짜를 나란히 배치했다. 시장 추이는 전체 폭, 당시 판단과 통합 회고는 432:720 비율로 표시한다.
- 선택 대상·기간을 바꿔도 하나의 회고와 질문별 답변이 유지된다. 저장 후에도 선택한 기간의 예측 원문을 함께 확인한다.
- 금리는 변화율 대신 %p, 지수는 변화율과 원시 변화량을 표시한다. 관측 불가·자료 누락·조회 실패·저장 실패 등 기존 상태 경계는 유지한다.
- P1-01·02와 모바일은 이 작업에 포함하지 않는다. 차트는 시계열 데이터로 그리며 정적 시안 이미지를 사용하지 않는다.
