# 담당 화면 UI

개발 서버의 `/dev/pages`에서 P0-03, P0-04(제출·이탈 모달), P0-05, P0-08-2를 확인한다. 대상 선택·상대 담당 페이지·모바일 전용 화면은 구현 범위에서 제외한다.

- `fixtures.ts`는 화면 예제이며 API 응답이나 실제 관찰값이 아니다. 네트워크 요청·MSW·영속 저장을 사용하지 않는다.
- `SessionProvider`는 개발용 메모리 저장·제출 어댑터다. 새로고침하면 초기화되며 제출한 예측은 피드백에 읽기 전용으로 표시된다.
- 화면 목록의 개발 데이터 링크로 대상 1개·3개·원/달러 환율을 검토할 수 있다. 대상 선택 화면은 추가하지 않는다.
- 상태 선택으로 로딩, 일시적 AI 오류, 인용/형식 검증 오류, 자료 부족, 관측 불가, 저장/제출 실패를 확인한다. 뉴스 조회 오류와 일시적 AI 오류의 재시도는 로딩 후 준비 상태로 돌아오는 개발 시뮬레이션이다. 인용/형식 오류는 재생성을 제공하지 않는다.
- 최종 제출은 현재 선택된 대상 전체의 방향과 공백 아닌 이유 최소 1개를 요구한다. 개별 이유는 선택이고 임시 저장은 미완성도 허용한다.
- 뉴스 예측 시작과 대상 변경은 콜백 연결점이다. 개발 미리보기만 미리 선택된 2개 대상으로 시작한다. 대상 선택 UI는 추가하지 않는다.
- 학습 기록·결과·회고·뉴스 탐색은 연결 경로만 제공한다. 다른 담당 화면의 개발 경계 안내는 제품 UI가 아니다.
- 실제 뉴스·피드백 API 및 상태 계약이 확정되면 개발 어댑터를 데이터 공급/액션 어댑터로 교체한다. 프런트 화면 타입을 서버 DTO로 간주하지 않는다.
- 화면 컴포넌트는 제품 라우트에서도 사용한다. 예제 데이터·상태 선택·메모리 저장 어댑터만 `/dev/pages/*`에서 개발 모드로 lazy import한다. 제품 빌드에는 예제 데이터와 데모 저장 흐름을 포함하지 않는다.
- 최초 피드백의 관찰 상태는 생성 상태와 독립된 `baseline_pending`·`scheduled`·`observing` 값으로 표시한다. 프런트에서 T0나 관찰 일정을 계산하지 않는다.
- 제품 라우트는 API 어댑터가 데이터를 공급하기 전 빈 상태를 표시한다. 기존 홈·로그인·탐색 라우트를 개발 미리보기로 덮어쓰지 않는다.
- 내부 이동·브라우저 뒤로가기는 data router의 `useBlocker`로 이탈 확인한다. 새로고침·탭 닫기는 브라우저 기본 경고를 사용한다.

검증 명령: `pnpm lint`, `pnpm build`, `git diff --check`. 별도 테스트 실행기는 추가하지 않는다.
